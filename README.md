# 中国 365 天宜居 / 宜旅行天气地图

把过去 5 年的天气记录烘焙成静态数据，按可调的舒适温度区间和降雨权重，生成一张覆盖全国地级市、可逐日查看的「宜居 / 宜旅行」评分地图。

**在线地址：https://listenzcc.github.io/china-weather-map/**

---

## 功能

- **中国地市着色地图**：370 个地级市（含南海诸岛九段线，符合地图规范），按当天评分做 choropleth 热力着色，可缩放 / 拖拽。
- **365 天时间轴**：拖动滑块定位到年内任意一天（1–365），或「播放全年」自动巡演。
- **双维度评分**：宜居、宜旅行两套预设，一键切换。
- **评分模式**：相对适宜度（按当天全国排名归一化，区分度最高）、绝对舒适度（看全国整体宜人程度）。
- **参数实时可调**：舒适温度下限 / 上限（默认 20–25 ℃）、降雨权重，改完地图秒变——评分在浏览器端计算，不重拉数据。
- **大号日期**：地图正中叠加「X月X日」，随滑块 / 播放更新。
- **城市打点**：每个城市在地图上叠加散点。
- **自然地理图层**：主要河流（蓝色折线）、湖泊（蓝点）、山脉（棕色三角 + 名称），侧栏可单独显隐。
- **全年日历 Top10**：主图下方一张日历热力图，每格 = 当天最优城市分数；悬停看当天全国 Top10，点击定位到那天。
- **年度总榜**：每座城市全年得分 = 每日适宜度分 × 365 天累加，横向条形排 Top30；切到该 tab 时，这些城市会在地图上用橙点 + 名称标注出来。

## 数据来源

- **天气**：[Open-Meteo Historical Archive](https://open-meteo.com/en/docs/historical-weather-api)（免费、无需 key）。拉取 2021–2025 年每个城市的 `temperature_2m_mean`（日均温）与 `precipitation_sum`（日降雨），按「同月同日」取 5 年均值聚合为 365 天序列（忽略 2/29）。
- **底图**：DataV.GeoAtlas 中国地市 GeoJSON（`china-geo.json`），平面投影，含南海诸岛九段线。
- **城市坐标**：从底图多边形质心提取（`cities.json`），用于天气查询与地图打点。
- **自然地理**：手工整理的 `geo-features.json`（河流走向用主要城市经纬度串成折线，湖泊 / 山脉用代表性坐标点标注）。

所有数据在构建期烘焙进静态 JSON，站点运行时**不发任何网络请求**，因此 GitHub Pages 秒开、可离线。

## 宜居与宜旅行是怎么实现的

两套评分共用同一套「原始舒适度」计算，区别只在预设参数。

### 1. 单日原始舒适度（0–1）

**温度项**用洛伦兹钟形，以舒适区间中心为峰、向两边平滑下降：

$$
T_{mid} = \frac{t_{min} + t_{max}}{2}, \qquad S_T(T) = \frac{1}{1 + \left(\frac{T - T_{mid}}{\sigma}\right)^2}
$$

- 落在中心最舒适（=1），舒适区内也有梯度，区间外不再硬归零、连续衰减到 0 附近。
- $\sigma$ 是钟形宽度：越小越「严格」，越大越「宽容温差」。

**降雨项**用饱和惩罚，雨越多越低：

$$
S_P(P) = \frac{1}{1 + P / k}
$$

- $k$ 越大越容忍雨；$P=0$ 时 =1。

两者加权合成单日原始舒适度：

$$
C = (1 - w)\, S_T + w\, S_P
$$

### 2. 两套预设（宜居 vs 宜旅行）

| 参数 | 宜居 | 宜旅行 | 含义 |
|---|---|---|---|
| $\sigma$（温度钟宽） | 7 | 12 | 宜居更严格，宜旅行更容忍温差 |
| $k$（降雨尺度，mm） | 12 | 8 | 宜居更容忍雨，宜旅行更怕雨 |
| $w$（降雨权重） | 0.30 | 0.50 | 宜旅行把降雨放在更重的位置 |

直觉上的差异：宜居偏「气候温和稳定」，温度卡得紧、雨天可室内活动所以影响小；宜旅行偏「晴天出行窗口」，能接受温度波动，但雨直接打乱行程，所以降雨权重更高、惩罚更陡。

### 3. 两种评分模式

- **绝对舒适度**：`score = 100 × C`，直接反映「今天实际有多舒服」。某天真正舒服的城市少，分数天然堆在中低区。
- **相对适宜度（默认）**：把当天所有城市的 $C$ 从小到大排名，做百分位数归一化到 0–100：

$$
  \text{score}_i = \frac{\text{rank}(C_i) - 1}{n - 1} \times 100
$$

最舒适的城市 = 100，最不宜 = 0，每天颜色铺满全谱。语义是「今天相对最该去哪」，区分度最高，也最契合宜旅行的使用场景。

### 4. 地图标注

- 主图 `geo` 坐标系上用 `scatter` 叠加每个城市的小点。
- 「年度总榜」视图下，复用已算好的每日最终分矩阵（缓存于 `dayStats`），累加 365 天排序取 Top30，用大号橙点 + 城市名标注在地图上，悬停显示年度累计分。

## 技术实现

- 前端：`index.html` 单文件，[ECharts](https://echarts.apache.org/) 5.5.1 通过 `dist/echarts.min.js` **本地引入**（离线、无 CDN 依赖）。
- 地图组合：`geo`（注册 china-geo）+ `map(geoIndex)` choropleth + `scatter`（城市点 / 自然地理 / Top30 标注）+ `lines`（河流折线）+ `graphic`（大号日期）；底部 `chart2` 用 `calendar` 热力图与 `bar` 年度榜，共用 tab 切换。
- 评分在浏览器端按当前参数即时重算；底层「每城每日原始舒适度矩阵」按参数指纹缓存，拖滑块只换天、不重算全年，保持流畅。

## 已知限制

- 当前 `data.json` 含约 200/370 城（演示用），其余城市在地图上渲染为灰色；本机跑一次 `fetch_weather.py` 即可补齐。
- 天气为 5 年气候均值，不代表某一年实际天气；评分是经验性舒适模型，参数可调，不声称绝对科学。

## 可扩展方向（当前未纳入评分的因子）

当前评分只用了**温度**与**降雨**两个气候量。以下因子会显著影响"宜居 / 宜旅行"的真实体验，但本期尚未纳入，留作后续补充：

- **海拔**：高海拔城市体感温度低于实测气温，且氧气分压、紫外线、昼夜温差都随海拔变化。可考虑按城市海拔对气温做体感修正（如气温递减率 ≈ 0.65℃/100m），或把海拔作为独立约束项。
- **交通可达性**：机场/高铁/高速网密度、到主要客源城市的时长。宜旅行维度尤其该纳入——"天气舒服但到了很难"会拉低体验。可叠加路网 POI 或城市间通达时间矩阵。
- **空气质量**：PM2.5 / 空气质量指数（AQI）季节性差异大，是宜居的核心因子之一。可接入历史 AQI 接口按相同"日历日均值"方式烘焙。
- **湿度 / 体感温度**：湿冷、湿热都显著影响体感，可引入体感温度（如酷热指数、风寒指数）替代裸气温。
- **极端天气与灾害**：台风、暴雪、沙尘暴等的发生频率，可作为扣分或屏蔽项。
- **日照时长 / 紫外线**：高纬冬季日照过短影响宜居感知；旅行维度可纳入晴日比例。

这些因子都建议以**与温度/降雨相同的聚合方式**（同月同日多年均值）烘焙进 `data.json`，再在前端 `rawComfort` / 预设权重里接入，保持"构建期烘焙、运行时可调"的整体架构不变。
